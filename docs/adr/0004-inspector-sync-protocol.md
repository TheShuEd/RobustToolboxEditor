# Протокол синхронизации инспектор ↔ текстовый редактор: карточки всего файла, без автопрокрутки

**Статус:** accepted

Инспектору (#11) нужен протокол, определяющий что он показывает относительно открытого текста и как обе поверхности не расходятся и не зацикливаются. Источник контента — активный текстовый редактор в фокусе (включая split view, переключение по смене фокуса между editor-группами); инспектор рендерит карточками **все** прототипы открытого файла разом (как предшественник `TheShuEd/SS14Editor`), а не единственный прототип под курсором. Привязка к позиции курсора отклонена целиком: ни автопрокрутка редактор→инспектор, ни обратная навигация инспектор→редактор — переход между карточками ручной. Anti-loop уже закрыт версионным игнором из #10 и не требует дополнительного протокольного элемента здесь.

## Рассмотренные варианты

- **Один прототип, привязанный к позиции курсора**, с автопрокруткой инспектора при движении курсора. Отвергнут: избыточная связность между поверхностями на данном этапе — при обычном сценарии редактирования нужный компонент и так остаётся на виду в обоих окнах, а привязка к курсору добавляет протокольную сложность (debounce скролла, идемпотентность обратной навигации) без подтверждённой необходимости.
- **Явный выбор прототипа из дерева индекса (#5), независимо от открытого редактора**, с pin-режимом. Отвергнут: требует отдельного протокола для случая, когда `applyEdit()` вынужденно открывает редактор как побочный эффект правки ещё не открытого документа (VS Code всегда показывает вкладку при правке неоткрытого файла) — усложнение без предъявленной пользователем потребности.
- **Карточки всего файла, ручная прокрутка, без привязки к курсору** (выбран). Простейший протокол: единственный триггер — смена активного/сфокусированного редактора (`onDidChangeActiveTextEditor`).

## Последствия

- Гранулярность undo для непрерывных полей (текстовый ввод, drag) — commit одним `applyEdit()` на blur/Enter, а не на каждое изменение: VS Code не даёт способа сгруппировать несколько вызовов `applyEdit()` в один шаг истории (нет группировки для `WorkspaceEdit`, в отличие от `TextEditor.edit()` с `undoStopBefore/After`, который к делу не относится).
- Обновление инспектора при ручной правке YAML — debounced re-parse на `onDidChangeTextDocument` (~200мс), тем же инкрементальным парсингом, что у индекса прототипов (#5); пока документ синтаксически сломан, инспектор показывает последнее валидное состояние с индикатором «не синхронизировано», не молчит и не показывает ошибку.
- Пустое состояние (не-YAML файл в фокусе либо редакторов не открыто) — явная подсказка открыть файл прототипа, а не заморозка последнего показанного файла.
- Автопрокрутка в любую сторону остаётся возможным дополнением v2, если понадобится, — протокол её не запрещает, просто не реализует сейчас.
