# schema-cli

One-shot C# CLI that reads the compiled DLLs of a **built SS14 fork** and
writes a single `metadata.json` describing every prototype, component and
`[DataDefinition]`: their fields (with `fieldKind`), recursive field type
trees, enum values, IL-scanned defaults, XML-doc summaries and inheritance
flags.

The extraction is the vendored metadata layer from the predecessor editor —
see [`../docs/vendored-schema-cli.md`](../docs/vendored-schema-cli.md). This
project only adds a ~30-line entry point.

│   ├── CtorDefaultsScanner.cs
│   ├── XmlDocReader.cs

│   └── Logger.cs
├── tests/                           verbatim xUnit suite (net10.0, run in Debug)

## Build

```sh
dotnet publish schema-cli/SS14Editor.SchemaCli.csproj -c Release -o <dir>
```

Produces `<dir>/SS14Editor.SchemaCli.dll` — framework-dependent, one managed
artifact for every OS, run through the shared `dotnet` host.

## Run

```sh
dotnet SS14Editor.SchemaCli.dll <forkRoot> <outputDir>
```

- `<forkRoot>` — a built fork's root, holding `bin/Content.Server` and/or
  `bin/Content.Client` (the upstream `OutputPath` convention).
- `<outputDir>` — where `metadata.json` and its `metadata.fingerprint` sidecar
  are written.

Exit codes: `0` success (or up-to-date no-op), `1` extraction error
(no DLLs, unreadable assembly), `2` bad arguments. Errors go to stderr.

### Fingerprint / no-op

The CLI computes a SHA-256 `sourceFingerprint` over `path|size|mtime` of every
input DLL plus its own version. If `<outputDir>/metadata.fingerprint` already
holds that value, the CLI exits in tens of milliseconds without rewriting
`metadata.json`. Any rebuild (which rewrites a DLL's bytes and mtime) changes
the fingerprint and forces a full re-scan.

## Tests

```sh
dotnet test schema-cli/tests/SS14Editor.SchemaCli.Tests.csproj
```

Run in **Debug** (the default). A few `CtorDefaultsScanner` fixtures read
`stfld` IL for `= false` / `= 0` / `= null` initializers, which the Release
optimizer elides.

## The committed fixture

`fixtures/metadata.json` was generated by running this CLI against a locally
built [`crystall-edge`](https://github.com/crystall-edge) fork. Later
TypeScript-core tickets read it as a schema snapshot.

Note: that fork build emits no `.xml` documentation files next to its DLLs, so
`summary` fields in this snapshot are empty. The CLI's XML-doc support
(`XmlDocReader`, with tests) is unaffected — a fork built with
`GenerateDocumentationFile` populates them.
